# AI Writing Guidelines

This document instructs you on how to write all text for this project. Read it. Follow it.

## Core Style

Write like Ernest Hemingway. Be concise. Be humble. Be functional. 

Do not use metaphors. Do not use clever words when simple words work. Keep sentences short. Write in the active voice. Tell the reader exactly what they need to know. Stop there.

## README Files

A README explains the software. It is not an advertisement. 

* State what the project does in one sentence.
* List the exact steps to install it.
* Show one clear example of how to use it.
* Remove filler words. Never use words like "amazing", "seamless", or "magic". Just state the facts.

## Commit Messages

A commit message is a permanent record of change. Write it clearly.

* **Structure:** `<type>: <subject>`
* **Length:** Limit the subject line to 50 characters.
* **Mood:** Use the imperative mood. Write "add button", not "added button" or "adds button".
* **Body:** If the change needs an explanation, write a body. Wrap the body at 72 characters.
* **Focus:** Explain *why* you made the change. The code already shows *how*.

Accepted types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.

## Code Comments

Good code explains itself. Name your variables and functions clearly so you do not need comments.

* Only write a comment to explain *why* a technical decision was made.
* Do not explain *what* the code is doing. We can read the code.
* Keep comments short. 
* If you change the code, update the comment immediately. A wrong comment is a lie.
