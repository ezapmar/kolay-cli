# Kolay MCP Server — Code Review

> Audit date: 2026-03-20
> Files reviewed: `app.py`, `mcp_server.py`, `server_middleware.py`, `security.py`, `rate_limiter.py`, `activity_log.py`

---

## 1. Technical Debt Found

### 1.1 `mcp_server.py` is a 1158-line monolith

Every tool, resource, prompt, progress helper, **and** the HTTP app factory live in a single file. This is the root cause of most other issues.

### 1.2 Duplicated `_sync_progress` boilerplate (5x)

The identical 4-line async-to-sync progress bridge is copy-pasted in:
- `team_availability_analysis`
- `turnover_risk_scan`
- `payroll_anomaly_detect`
- `analyze_employee_wellbeing`
- `get_smart_rest_plan`

```python
# This exact block appears 5 times:
async def _progress(step, total, msg):
    await ctx.report_progress(progress=step, total=total)
    await ctx.info(msg)
def _sync_progress(step, total, msg):
    import asyncio
    asyncio.get_event_loop().create_task(_progress(step, total, msg))
```

### 1.3 Triple token injection path (env + 2 ContextVars)

`server_middleware.py` sets the token in **three** places per request:
1. `KOLAY_TOKEN_CTX` (ContextVar from `security.py`)
2. `request_token` (ContextVar local to middleware)
3. `os.environ["KOLAY_API_TOKEN"]` (process-wide mutation)

The env var mutation is thread-unsafe in multi-tenant scenarios. `request_token` is a dead import -- nothing reads it downstream.

### 1.4 Sentinel cache that never caches

`security.py` defines `_token_cache` + `_SENTINEL` but `resolve_token()` always calls `_resolve_uncached()`. The middleware also resets the sentinel manually on every request. The cache is effectively dead code.

### 1.5 `app.py` references undefined `_log()`

Line 70: `_log(f"\nKolay IK MCP Proxy...")` -- `_log` is defined in `server_middleware.py` but never imported into `app.py`. This crashes at runtime if `__main__` is executed.

### 1.6 Redundant `__import__` calls in `commands/mcp.py`

Options use inline `__import__("os")` instead of a top-level `import os`:

```python
host: str = typer.Option(
    "0.0.0.0" if "PORT" in __import__("os").environ else "127.0.0.1", ...
)
```

### 1.7 Inline `import json` scattered throughout

Resources (`reason_codes`, `turkish_holidays`, `leave_types`, `org_chart`) each do `import json` inside the function body. The module already has top-level imports.

### 1.8 `filter` shadows built-in

Multiple tools use `filter` as a parameter name (a Python built-in), which makes debugging harder.

## 2. Architecture Improvements (Proposed)

### 2.1 Split the monolith

```
mcp_server.py              -> core setup only (FastMCP init, resources)
mcp/tools_people.py        -> person_* tools
mcp/tools_leaves.py        -> leave_* tools
mcp/tools_analytics.py     -> HR analytics + wellness tools
mcp/tools_misc.py          -> calendar, transaction, unit, approval
mcp/prompts.py             -> all @mcp.prompt() definitions
```

Each sub-module gets a `register(mcp)` function called from the main server file.

### 2.2 Extract a shared progress helper

```python
# mcp/progress.py
def sync_progress_bridge(ctx: Context):
    """Return a (step, total, msg) -> None callback that bridges async ctx."""
    ...
```

Eliminates 5 copies of the same code.

### 2.3 Simplify token flow to single ContextVar

- **Keep**: `KOLAY_TOKEN_CTX` in `security.py`
- **Remove**: `request_token` ContextVar from `server_middleware.py`
- **Remove**: `os.environ["KOLAY_API_TOKEN"]` mutation (the env-var writeback)
- **Remove**: Manual `_SENTINEL` / `_token_cache` resetting

`resolve_token()` should read: ContextVar -> env var (read-only) -> keyring -> config file. No writeback, no mutation.

### 2.4 Standardise tool docstrings

Current format is inconsistent -- some say `[WRITE]`, some say `[DESTRUCTIVE]`, some say neither. Proposed standard:

```
"""[READ|WRITE|DESTRUCTIVE] One-line summary.

Args explained naturally. Dates in YYYY-MM-DD.
person_id: Employee UUID from person_list.
"""
```

### 2.5 Centralise `filter_items_silent` calls

6 tools repeat the same pattern: call a service, then optionally filter. A decorator or wrapper could handle this:

```python
@filterable(keys=["firstName lastName", "workEmail"])
def person_list(...): ...
```

## 3. Optimisation Highlights

| Area | Current | Proposed | Impact |
|---|---|---|---|
| Token injection | 3 paths, env writeback | 1 ContextVar | Thread safety, simplicity |
| Progress bridge | 5 copies, 20 lines | 1 helper, 4 lines | Maintainability |
| `mcp_server.py` | 1158 lines, 1 file | ~6 files, ~200 lines each | Reviewability, merge conflicts |
| `_token_cache` | Dead code + sentinel | Remove entirely | Clarity |
| `request_token` ContextVar | Unused downstream | Remove | Less surface area |
| `app.py` `_log` | Crashes on `__main__` | Import or inline `print` | Correctness |
| `filter` param name | Shadows built-in | Rename to `match` or `q` | Python hygiene |

## 4. Security Notes

Things that are **already done well**:
- `@require_auth` decorator with structured error responses
- Rate limiter is opt-in, per-token, sliding-window -- solid design
- Activity log redacts long strings and never logs response payloads
- JWT validation has clock-skew leeway
- Gatekeeper is a bonus layer, not a hard gate -- correct for MCP

Things to **tighten**:
- `os.environ["KOLAY_API_TOKEN"]` mutation is a shared-state vulnerability in async contexts. Remove the writeback.
- `_send_json` in middleware should set `Cache-Control: no-store` on 401 responses.
- Commented-out JWKS verification block in `security.py` (lines 360-374) should be removed or promoted to a feature flag.

## 6. Verdict

The prompt the user drafted is **well-targeted**. Every concern it raises maps to a real issue found in the codebase:

| Prompt Concern | Found? | Severity |
|---|---|---|
| Eliminate redundancy | Yes -- progress bridge (5x), filter pattern (6x) | Medium |
| Standardize tool definitions | Yes -- inconsistent docstring tags | Low |
| Refine error handling | Partially done -- `@require_auth` is good, but `app.py` `_log` crashes | Medium |
| Optimize stateless proxy logic | Yes -- triple token injection is the biggest tech debt | High |
| Prune over-engineering | Yes -- dead cache, unused ContextVar, commented JWKS | Low |
| Maintain vibe | Clean -- tags like `[auth]` are good, no excessive logging found | Fine |

**Bottom line:** The codebase works and is well-tested (653 passing tests), but the token-injection path and the monolith file are the two things that would cause real pain at scale. Fix those first; the rest is polish.
