Dead code removed. See 1.3 above.

## 4. Security Notes (Updated)

Things **already done well**:
- `@require_auth` decorator with structured error responses
- `@requires_permission` decorator with JWT claim-based permission checking
- Rate limiter is opt-in, per-token, sliding-window -- solid design
- Activity log redacts long strings and never logs response payloads
- HMAC-SHA256 execution receipts for verifiable audit trails
- JWT validation has clock-skew leeway and optional signature verification
- Gatekeeper is a bonus layer, not a hard gate -- correct for MCP
- `Cache-Control: no-store` is set on 401 responses in `_send_json`

**New security layers added (2026-03-23):**
- PII Masking middleware (opt-in) -- deterministic HMAC pseudonymization of names, emails, IDs
- Payload Padding middleware (opt-in) -- uniform response sizes defeat traffic analysis
- Config Encryption at rest (opt-in) -- Fernet + PBKDF2 machine-derived key
- mTLS sidecar config (infra) -- NGINX reverse proxy with client cert verification

**New Smart Proxy security properties (2026-03-24):**
- `search_employees` / `get_employee_statistics` are protected by `@require_auth` -- same guardrails as all other tools
- `get_cache_status` intentionally has NO auth (operational diagnostic, leaks no PII)
- Mock data generator uses deterministic seed (`Random(42)`) -- no entropy leakage
- Manifest signing uses ephemeral ECDSA P-256 keys -- private key is never persisted by default
- JWS follows RFC 7515 / RFC 7518 Section 3.4 (fixed-size r||s signature format)

Things **tightened during this review run**:
- ~~`os.environ["KOLAY_API_TOKEN"]` mutation~~ FIXED
- ~~`Cache-Control: no-store` on 401 responses~~ FIXED (was missing from `APIKeyMiddleware._send_401` in `mcp_server.py`; already present in `server_middleware.py`)
- ~~Commented-out JWKS block~~ REMOVED
- ~~`_GLOBAL_LOOKUP` thread-safety bug in `pii_masker.py`~~ FIXED -- replaced with per-call local dict
- ~~Content replacement gap in `PIIMaskingMiddleware`~~ FIXED -- static-only masking now correctly updates response

Remaining:
- `__import__` usage in `commands/mcp.py` is unconventional but not a security issue
- `get_cache_status` exposes `entry_count` and `age_seconds` -- not PII, but reveals cache population timing. Acceptable for operators, worth documenting.

## 6. Verdict (Updated)

**Previous verdict (2026-03-23):** Both major pain points (token injection, monolith) fully resolved. Codebase production-ready, only cosmetic P2/P3 items remained.

**Current state (2026-03-24):** Smart Proxy layer added with TTL caching, server-side projection, hard-limit truncation, zero-data aggregation tools, and a verifiable API manifest. The codebase has gone from 686 to **717 passing tests** (31 new). All P0 and P1 items are done. Only cosmetic P2/P3 items remain (3 dead-code items, inline imports, one `filter` shadow, `@filterable` decorator).

**Bottom line:** The codebase is production-ready. The Smart Proxy addresses all five anti-patterns from the original brief: context bloat (projection + 50-row cap), API overload (TTL cache), zero-trust gap (already existed + maintained), agentic discoverability (JWS manifest), and LLM math offloading (aggregation tools). Remaining tech debt is 3 one-line dead-code removals and cosmetic polish.

### 8.3 Design Quality

| Aspect | Assessment |
|---|---|
| **TTL Cache** | Clean stdlib-only implementation. Thread-safe with `threading.Lock`. Uses `time.monotonic()` (correct for elapsed time, not affected by system clock changes). Lazy expiry on `get()` (no background thread needed). |
| **Projection** | Simple dict comprehension in `_project()`. Correct -- only whitelisted keys pass through. Default projection is 6 fields (vs 50+ in raw API). |
| **Truncation** | Hard-capped at `min(limit, 50)`. Warning metadata is appended as `_meta.warning` -- LLM-friendly self-correction pattern. |
| **Aggregation** | 4 metrics (`headcount`, `average_age`, `department_distribution`, `tenure_distribution`). All computed in-code, never returning raw rows. Graceful handling of missing `birthDate`/`employmentStartDate`. |
| **Manifest** | Follows RFC 7515 (JWS) and RFC 7518 Section 3.4 (ES256 fixed-size signature). Uses `cryptography` lib (already a transitive dep). |
| **Test coverage** | 31 tests, all passing. Cache expiry tests use `time.sleep(1.1)` -- slightly slow but correct. Manifest tests use `pytest.importorskip("cryptography")` for graceful degradation. |
